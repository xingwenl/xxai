# 开发示例技能

## 什么时候用

用户给出一段零散文本（会议记录、需求草稿、聊天片段），并要求「整理成要点」「提炼结论」
「列成清单」时使用。

## 步骤

1. 通读原文，**不要补全原文没有的事实**。原文自相矛盾或含糊的地方留到第 4 步。
2. 提炼 3 到 7 条要点，每条一行，用 `- ` 开头；一条只讲一件事。
3. 按「结论 → 依据 → 待办」三组排列要点；某一组没有内容就整组省略，不要写空标题。
4. 结尾固定加一行 `待确认：`，列出原文没写清楚的地方；一条都没有就写 `待确认：无`。

## 输出格式

```text
## 结论
- ...

## 依据
- ...

## 待办
- ...

待确认：...
```

## 注意

- 只做整理，不做决策；不要替用户拍板。
- 原文超过 2000 字时，先按主题切分再逐段整理。
- 需要更多细节时读同目录下的 `reference.md`，不要一次性把所有规则都塞进回答。
