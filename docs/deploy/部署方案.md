# ai-base 部署方案（backend + front）

> 目标：将 `apps/backend`（FastAPI 后端）与 `apps/front`（前端）部署到一台 Linux 服务器，对外通过 HTTPS 提供访问。
> 本文档基于仓库现状编写，所有命令在服务器上执行（除非特别说明）。

## 1. 现状盘点

| 项目 | 技术栈 | 产物 |
| --- | --- | --- |
| `apps/backend` | FastAPI + SQLAlchemy(异步) + Alembic + Celery + PostgreSQL 16 + Redis 7 + pgvector | Docker 镜像（`apps/backend/Dockerfile`） |
| `apps/front` | React 19 + Vite 8 + TanStack Router | 静态资源 + Nginx（`apps/front/Dockerfile`、`nginx.conf`） |

根目录已有 `docker-compose.yml`，定义了完整服务集合：

- `db`（postgres:16-alpine，仅绑定宿主机 127.0.0.1）
- `redis`（redis:7-alpine，仅绑定宿主机 127.0.0.1）
- `api`（uvicorn，启动时自动执行 `alembic upgrade head`）
- `worker`（Celery 任务消费者，与 api 共用同一镜像）
- `wechat-bot-worker`（默认关闭，`WECHAT_BOT_ENABLED=false`）
- `skill-runner`（技能沙箱，默认随 compose 启动，内部网络）
- `front`（Nginx 托管静态资源，并将 `/api/` 反向代理到 `api:8000`）
- `ollama` / `ollama-init`（可选 profile `local-embedding`，默认不启动）

前端 Nginx 已配置 `/api/` → `api:8000` 的反向代理，因此**前后端同源部署**是仓库的原生形态：浏览器只访问前端域名，所有 API 请求走同一域名下的 `/api/*`，天然规避 CORS 问题。

## 2. 方案选型

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 单机 Docker Compose（裸端口） | 与仓库现状完全吻合，一条命令启动 | 无 HTTPS，默认密码需改 | 快速验证用 |
| B. 单机 Docker Compose + Caddy/Nginx 反代做 HTTPS | 生产推荐形态，自动证书，安全 | 需域名并解析到服务器 | **推荐** |
| C. 云托管 / K8s | 弹性伸缩、高可用 | 成本高、运维复杂，本规模项目过度设计 | 暂不采用 |

**决策：方案 B。** 单台服务器 + Docker Compose 承载全部服务，宿主机（或同网络容器）运行 Caddy 提供 HTTPS，对外只暴露 443（和可选 80 跳转）。

## 3. 目标架构

```text
用户浏览器
   │  https://your.domain.com
   ▼
Caddy（443，自动 HTTPS）
   │
   ▼
front 容器（Nginx:80）
   ├── /          → 静态资源（React 构建产物）
   └── /api/*     → 反向代理到 api:8000
                        │
                        ├── db（postgres:5432，仅内网）
                        ├── redis（6379，仅内网）
                        └── worker（Celery，消费 redis 队列）
```

可选扩展：`ollama`（本地 embedding）、`wechat-bot-worker`、`skill-runner` 均已在 compose 中定义，按需启用。

## 4. 服务器要求

- 系统：Ubuntu 22.04+ / Debian 12+（其他发行版命令需自行调整）
- 资源：最低 2 核 4G；推荐 4 核 8G（worker 承担文档解析与向量化，吃内存）
- 磁盘：40G 以上（镜像、`postgres_data` 数据卷、`apps/backend/storage` 附件与技能文件、日志）
- 网络：公网开放 `80`、`443`；`db`/`redis` 已绑定 `127.0.0.1`，不要暴露到公网
- 域名：一个已解析到该服务器 IP 的域名（HTTPS 必需；无域名可先用 IP 验证）

## 5. 部署步骤

### 5.1 服务器初始化（一次性）

```bash
# 安装 Docker（Ubuntu/Debian）
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker

# Compose 插件（新版 docker 已自带；确认）
docker compose version
```

### 5.2 拉取代码

推荐在服务器上用 git 拉取并固定发布版本：

```bash
cd /opt
git clone <你的仓库地址> ai-base
cd ai-base
git checkout <发布 tag 或 commit>   # 例如 v0.1.0，保证可回滚
```

如果不方便用 git，也可将仓库 `rsync`/`scp` 上传，但会失去后续 `git pull` 升级的便利。

### 5.3 配置环境变量

```bash
cp .env.example .env
vim .env   # 或 nano
```

`.env` 必改项（生产）：

| 变量 | 说明 |
| --- | --- |
| `DB_PASSWORD` | 数据库密码，改为强随机值 |
| `APP_ENV` | 改为 `production` |
| `APP_VERSION` | 与发布版本一致 |
| `OPENAI_API_KEY` / `OPENAI_BASE_URL` | 模型网关凭据（本地网关则指向内网地址） |
| `ATTACHMENT_EMBEDDING_*` | 附件向量化服务凭据（如使用） |
| `EMBED_ORIGIN` | 改为生产域名，如 `https://your.domain.com` |
| `QUOTA_ENABLED` | 按需 `true` 开启配额 |
| `SKILL_RUNNER_SHARED_SECRET` | 改为强随机值（启用 skill-runner 时） |
| `WECHAT_BOT_ENABLED` | 默认 `false`，不需要微信机器人就保持关闭 |

> 注意：`POSTGRES_VOLUME_NAME` 默认 `backend_postgres_data` 且为 `external: true`，首次部署必须先创建该卷（见 5.4），否则 `docker compose up` 会报"外部卷不存在"。

### 5.4 创建数据卷（首次部署必做）

```bash
docker volume create backend_postgres_data
```

### 5.5 构建并启动核心服务

```bash
# 构建镜像（api 与 worker 复用 backend 镜像；front 构建时注入 VITE_API_URL）
docker compose build api worker front

# 启动核心链路
docker compose up -d db redis api worker front
```

- `api` 容器启动时自动执行 `alembic upgrade head`，无需手动迁移
- `skill-runner` 默认随 compose 启动；`ollama` 属于 profile，默认不启动
- 端口说明：`front` 默认映射宿主机 `5173`，`api` 映射 `8000`（生产最终由反代接管，可用 compose override 收紧为仅内网）

### 5.6 验证

```bash
docker compose ps                 # 全部 healthy / running
curl -s http://127.0.0.1:8000/api/v1/system/health  # 后端健康检查
curl -sI http://127.0.0.1:5173    # 前端首页
curl -s http://127.0.0.1:8000/metrics | head  # Prometheus 指标（如启用）
```

浏览器访问 `http://服务器IP:5173`，确认登录、对话、知识库等页面正常。

## 6. HTTPS 反代（生产必做）

推荐用 Caddy 容器（自动申请/续期证书），与现有 compose 放同一网络。新建 `deploy/docker-compose.prod.yml` 示例：

```yaml
services:
  caddy:
    image: caddy:2-alpine
    ports:
      - "80:80"
      - "443:443"
    environment:
      - DOMAIN=your.domain.com
    volumes:
      - ./deploy/Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - front
    restart: unless-stopped

volumes:
  caddy_data:
  caddy_config:
```

`deploy/Caddyfile`：

```caddyfile
your.domain.com {
    reverse_proxy front:80
}
```

启动：

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d caddy
```

> 域名需先解析到服务器 IP；证书由 Caddy 自动签发。若不用 Caddy，也可在宿主机装 Nginx，`server { listen 443 ssl; location / { proxy_pass http://127.0.0.1:5173; } }`，并用 certbot 申请证书。

## 7. 数据备份与恢复

数据 = PostgreSQL 数据卷 + `apps/backend/storage`（附件/技能文件）+ `apps/backend/logs`。

```bash
# 备份数据库（脚本内执行）
docker compose exec -T db pg_dump -U "${DB_USER:-root}" -d "${DB_NAME:-ai_db}" \
  > backup-$(date +%F).sql

# 备份附件目录
tar czf storage-$(date +%F).tar.gz apps/backend/storage
```

恢复：

```bash
cat backup-2026-09-01.sql | docker compose exec -T db psql -U root -d ai_db
```

建议 crontab 每日备份，保留最近 N 份；备份文件存放在服务器以外的位置（对象存储/另一台机器）。

## 8. 升级与回滚

升级（先备份！）：

```bash
cd /opt/ai-base
git pull
docker compose build api worker front skill-runner
docker compose up -d db redis api worker front skill-runner
```

`api` 启动时自动执行 `alembic upgrade head`；升级前确认新版本 migrations 向下兼容，必要时先手动备份。

回滚：

```bash
git checkout <上一个 tag>
docker compose build api worker front skill-runner
docker compose up -d
```

> 若迁移不可逆，回滚前需先恢复数据库备份。

## 9. 监控与日志

- 日志：`docker compose logs -f api worker front`；后端日志落盘 `apps/backend/logs/app.log`（自动轮转）
- 指标：后端已集成 `prometheus-client`，`/metrics` 输出 Prometheus 格式，可按需接入 Prometheus + Grafana
- 健康检查：compose 中 `db`/`redis`/`skill-runner` 已配置 healthcheck；建议为 `api` 增加 `/health` 探活与进程守护（`restart: unless-stopped` 可在 compose 中补充）

## 10. 安全清单

- [ ] 修改 `DB_PASSWORD`，不要使用示例默认值
- [ ] `SKILL_RUNNER_SHARED_SECRET` 使用强随机值
- [ ] `db`/`redis` 仅内网访问（compose 已绑定 `127.0.0.1`，不要改成 `0.0.0.0`）
- [ ] 生产通过 HTTPS 反代访问，不直接暴露 `8000`/`5173` 端口到公网
- [ ] 定期执行数据库与附件备份
- [ ] 保持基础镜像与依赖更新（`docker compose build --pull`）

## 11. 常见问题

- **`external volume "backend_postgres_data" not found`**：未执行 5.4，先 `docker volume create backend_postgres_data`。
- **构建报 `Temporary failure in name resolution` / pip 拉不到 poetry**：国内服务器访问 `pypi.org` 常被 DNS 污染。后端三个 Dockerfile 已默认把 pip 源切到清华镜像（`PIP_INDEX_URL`），前端 Dockerfile 已切到 npmmirror，无需手动处理；若你的网络更适合其他源，可覆盖：
  ```bash
  docker compose build --build-arg PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/ api
  ```
- **api 启动报 `listen tcp4 0.0.0.0:8000: bind: address already in use`**：docker compose 合并 `-f` 文件时 `ports` 是拼接而非覆盖，旧版 `deploy/docker-compose.prod.yml` 会让 api/front 同时绑定 `0.0.0.0` 与 `127.0.0.1` 两个端口，互相冲突。已改用 `!override` 标签修复；服务器上需先清理残留容器与 docker-proxy 再部署：
  ```bash
  cd /root/xxai
  git pull
  docker compose down
  systemctl restart docker
  bash deploy/deploy.sh
  ```
- **迁移失败导致 api 反复重启**：`docker compose logs api` 查看 Alembic 报错；修复后重启 `api`。
- **页面刷新 404**：前端 Nginx 已配置 `try_files ... /index.html`，正常不会出现；若自定义反代需保留该规则。
- **跨域报错**：同源部署（走 `/api/` 反代）不受影响；若前后端分离部署，需同步修改后端 CORS `allow_origins` 与 `EMBED_ORIGIN`。
- **微信机器人连不上**：`wechat-bot-worker` 通过 `host.docker.internal` 访问宿主机模型网关，Linux 上依赖 compose 中已配置的 `extra_hosts`；不需要时保持 `WECHAT_BOT_ENABLED=false`。

## 12. 下一步

本方案基于现有 `docker-compose.yml` 给出。落地时建议在 `deploy/` 目录补齐以下文件并纳入版本管理：

1. `docker-compose.prod.yml`（Caddy 反代 + 端口收紧 + `restart` 策略）
2. `deploy.sh` / `backup.sh`（一键部署与备份脚本）
3. `deploy/.env.prod.example`（生产环境变量模板，避免把 `.env` 提交进仓库）

按需由 AI 生成并验证后，即可在服务器上按第 5 节执行。

## 13. 附录：CentOS 7 快速开始（推荐用仓库脚本）

本仓库已提供开箱即用的部署脚本（`deploy/` 目录），适配 CentOS 7：

| 文件 | 作用 |
| --- | --- |
| `deploy/install-docker.sh` | 环境准备：已有 Docker 则跳过（不降级）；确保 compose 可用；放行 SELinux/防火墙 |
| `deploy/docker-compose.prod.yml` | 生产覆盖：api/front 仅监听 127.0.0.1，核心服务自动重启 |
| `deploy/deploy.sh` | 一键部署：校验 `.env` → 建卷 → 构建 → 启动（含 `skill-runner`，微信机器人按配置可选）→ 健康检查 → 部署 nginx 配置 |
| `deploy/nginx/ai-base.conf` | 宿主机 nginx 反代（上传限制 100m、WebSocket、SSE 长连接） |
| `deploy/backup.sh` | 数据库 + 附件备份，支持 `--install-cron` 定时 |
| `deploy/.env.prod.example` | 生产环境变量模板（复制为 `.env` 后修改） |

### 服务器上的执行顺序

```bash
cd /root/xxai

# 1. 环境准备（已装 Docker 26.x 会跳过安装，不降级）
bash deploy/install-docker.sh

# 2. 生成并编辑生产环境变量（必改 DB_PASSWORD 等）
cp deploy/.env.prod.example .env
vim .env

# 3. 一键部署（构建 + 启动 + 应用 nginx 配置）
# 注意：先 git pull 拉到最新代码（含国内镜像源修复），再执行部署
git pull
bash deploy/deploy.sh

# 4. 验证
curl -s http://127.0.0.1:8000/api/v1/system/health   # 后端健康
curl -sI http://127.0.0.1:5173/                       # 前端容器
# 浏览器访问 http://8.153.87.79/（宿主机 nginx 已接管 80 端口）

# 5. 首次备份 + 开启每日自动备份
bash deploy/backup.sh
bash deploy/backup.sh --install-cron
```

### 开启 HTTPS（有域名时）

```bash
yum install -y epel-release certbot python2-certbot-nginx
certbot --nginx -d 你的域名
```

certbot 会自动改写 `/etc/nginx/conf.d/ai-base.conf` 并续期证书。
