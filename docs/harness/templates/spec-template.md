# 设计说明

## 目标

- 说明本次 request 解决什么问题
- 说明目标用户、调用方或受影响对象
- 说明完成后应产生什么可验证结果
- 简要引用 `research.md` 的关键调研结论和最终方案

## 范围

- 明确本次包含的功能、接口、文档或配置项
- 明确涉及的目录或模块
- 若是增量任务，说明与原闭环的关系

## 非目标

- 写明这次不会顺手做的内容
- 写明哪些相关问题会留到后续 request 处理

## 风险

- 说明回归风险、兼容性风险、联调风险、数据风险
- 若暂无显著风险，也要明确写“当前未识别到高风险运行时变更”

## 停点判断

- 是否涉及架构边界变化
- 是否涉及数据模型变化
- 是否涉及 API 契约变化
- 是否涉及鉴权或权限行为变化
- 若任一项为“是”，必须明确写“进入实现前需人工确认”

## 验收标准

- 用可检查、可验证的句子描述完成标准
- 尽量避免只写“功能正常”这类模糊描述
- 若是文档工程任务，也要写清要补齐哪些文档资产
