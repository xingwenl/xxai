# Skill Zip 导入调研

## 调研问题

- 技能管理如何支持直接上传 `.zip` 包，并解析市面常见 Skill 包？
- 如果包内包含 `scripts/`、`references/`、`assets/` 等文件，如何保留完整包资产并让运行时可受控使用？
- 如何通过显式权限控制包内脚本执行，同时保留 zip 上传的基础安全校验？

## 功能复杂度

- 级别：核心功能，带安全风险。
- 选择理由：本次不再只是解析 `SKILL.md`，而是引入技能包持久化、包文件索引、脚本执行权限和运行时约束，涉及架构边界、数据模型、API 契约和权限行为变化。
- 最低调研要求：至少参考一个官方来源和一个成熟实践，补充压缩包安全处理与受控执行约束。

## 参考依据

### 来源 1

- 类型：官方文档
- 名称：OpenAI Codex / ChatGPT Skills 文档
- 链接：https://learn.chatgpt.com/codex/build-skills
- 版本或发布日期：2026-08-04 在线文档查询；本地官方手册脚本因 `developers.openai.com` HEAD 403 未能直接拉取，改用公开官方学习页作为依据。
- 调研日期：2026-08-04
- 核心做法：Skill 以目录为载体，核心入口是 `SKILL.md`，可按需包含 `scripts/`、`references/`、`assets/` 等辅助目录；描述元数据通常写在 `SKILL.md` 顶部 frontmatter 中。
- 对本项目的启发：技能包不能只抽取单个 Markdown，而应保留包内目录结构、文件索引和元数据；脚本与资源文件需要作为包资产纳入权限控制。

### 来源 2

- 类型：官方文档
- 名称：OpenAI Codex 插件结构说明
- 链接：https://developers.openai.com/codex/plugins/build
- 版本或发布日期：2026-08-04 在线查询
- 调研日期：2026-08-04
- 核心做法：插件是可安装 bundle，包含 `.codex-plugin/plugin.json`，并可携带 `skills/` 目录；一个插件包里可能包含多个 Skill。
- 对本项目的启发：导入层必须支持插件包内的 `skills/<skill-name>/SKILL.md` 结构，解析出多个技能条目，并保留包清单用于后续安装和权限判断。

### 来源 3

- 类型：成熟实践 / 安全基线
- 名称：Python `zipfile` 安全解压实践与 Zip Slip 风险
- 链接：https://docs.python.org/3/library/zipfile.html
- 版本或发布日期：Python 3.12 文档；调研日期 2026-08-04
- 核心做法：读取压缩包成员时应检查文件名、大小和目标路径，避免路径穿越、绝对路径、过大文件和过多条目；解析内容可直接从 zip 条目读取，但落库前仍需校验和受控展开。
- 对本项目的启发：后端需要做 zip 安全校验、受控解压与目录白名单；限制 zip 总大小、条目数量、单个文件大小；拒绝 `../`、绝对路径、空文件名和异常压缩包。

## 方案比较

| 方案 | 优点 | 限制 | 与本项目的匹配度 |
|---|---|---|---|
| A. 上传 zip 后只提取 `SKILL.md`，其余文件丢弃 | 改动最小，安全面最窄 | 无法承载脚本和资源文件，导入后会严重降级 | 低，不能满足目标 |
| B. 上传 zip 后保留包资产，建立包清单和受控脚本权限 | 能兼容市面技能包，保留多文件结构，未来可做运行时执行 | 需要新增数据模型、存储、权限和运行时约束 | 高，符合当前目标 |
| C. 前端本地解压并上传结构化结果 | 后端压力小 | 安全策略分散，难以统一审计，无法保证包完整性 | 中低 |
| D. 只允许用户粘贴 `SKILL.md` 文本 | 最简单 | 不满足“直接上传 zip” | 低 |

## 最终决策

- 选择方案：方案 B，上传 zip 后保留包资产、建立包清单，并通过显式权限控制脚本执行。
- 选择原因：只有 B 能真正承载市面技能包里常见的多文件结构、脚本和资源文件，同时把执行风险收敛到可审计的权限位和运行时边界。
- 不选择其他方案的原因：A 会丢失包内资源，无法满足需求；C 将安全校验和完整性判断拆到前端，审计和复用都不可靠；D 不满足需求。
- 对后续 spec、plan 或人工确认的影响：本次会同时触发架构边界、数据模型、API 契约和权限行为变化，必须先完成人工确认，再进入实现。

## 剩余风险

- 资料时效性：OpenAI 官方技能/插件结构可能继续演进，当前方案只保证兼容 `SKILL.md` 和插件内 `skills/*/SKILL.md` 的主流结构。
- 与本项目上下文的差异：当前系统原本是数据库模板模型，本次会向“包 + 元数据 + 受控执行”演进，代码和表结构都要跟上。
- 尚未验证的假设：包内脚本究竟以何种沙箱执行最合适，需要结合后端现有运行机制和可用依赖再定。
