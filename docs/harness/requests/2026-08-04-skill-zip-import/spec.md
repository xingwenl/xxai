# Skill Zip 导入规格

## 目标

- 在技能管理页面支持上传 `.zip` 技能包。
- 后端解析市面常见 Skills 包结构，保留包资产，并生成可安装的技能包记录。
- 用户可基于解析结果创建当前平台下的技能，创建逻辑在保留现有技能表能力的同时，引入包级元数据和脚本权限。
- 基于调研结论，本阶段要做包文件持久化、目录索引、受控执行权限和运行时消费，不再只做导入预填。

## 范围

### 后端

- 新增 `POST /api/v1/platforms/{platform_id}/skills/import`：上传 zip 并创建技能包记录。
- 新增 `GET /api/v1/platforms/{platform_id}/skill-packages`：分页查看已导入技能包。
- 新增 `GET /api/v1/platforms/{platform_id}/skill-packages/{package_id}`：查看包清单、候选技能和权限状态。
- 新增 `PATCH /api/v1/platforms/{platform_id}/skill-packages/{package_id}`：切换脚本执行权限、启停包级状态。
- 请求类型：`multipart/form-data`，字段名 `file`，仅接受 `.zip`。
- 响应内容：技能包记录、候选技能列表、包类型、文件清单摘要、警告信息。
- 支持结构：
  - zip 根目录或单层目录内存在 `SKILL.md` / `skill.md`。
  - 插件包内存在 `.codex-plugin/plugin.json` 和 `skills/<slug>/SKILL.md`。
  - 一个 zip 中多个 `SKILL.md` 返回多个候选项。
  - `scripts/`、`references/`、`assets/` 作为包资产持久化，不丢弃。
- 解析规则：
  - `SKILL.md` 顶部 YAML frontmatter 中的 `name` 映射为技能名称。
  - frontmatter 中的 `description` 映射为技能描述。
  - 目录名或文件名派生 `slug`，并转成当前系统允许的 `^[a-z0-9][a-z0-9_-]*$`。
  - 去掉 frontmatter 后的 Markdown 正文映射为 `instruction_template`。
  - `parameter_schema` 和 `lifecycle_hooks` 默认 `{}`。
- 安全限制：
  - 限制 zip 总大小、条目数、单个文件大小。
  - 拒绝路径穿越、绝对路径、空路径和异常 zip。
  - 解压到受控存储区，不写入工作目录。
  - 脚本执行必须受权限控制，默认关闭。
- 权限：复用当前 `_require_admin` 平台管理员校验，并新增“脚本执行开关”作为包级权限字段。

### 前端

- 在 `apps/front/src/features/skills/index.tsx` 增加 zip 导入入口。
- 用户选择平台后可上传 zip 并查看包详情、候选技能和脚本权限状态。
- 支持启用/关闭“允许执行包内脚本”的开关。
- 导入成功后保留技能包记录，并可从包记录生成或同步技能表单。
- 导入失败时展示后端错误信息，不创建技能包。

## 非目标

- 不做市场分发、版本商店或多租户外部分享。
- 不把脚本执行权限等同于无条件执行，仍需受沙箱和白名单约束。
- 不支持 tar、rar、目录拖拽或远程 URL 导入。
- 不支持任意代码直通宿主进程。

## 风险

- API 契约变化：新增上传、包查询和脚本权限接口，前后端和外部客户端需按新契约联调。
- 数据风险：需要新增技能包与包文件索引相关结构，并处理技能删除时的包资产清理。
- 权限风险：脚本执行开关会改变运行时行为，必须默认关闭并只允许平台管理员切换。
- 兼容性风险：不同平台的 Skill 包元数据可能不完全一致，本阶段以 `SKILL.md` 为准，未知字段只忽略或作为警告返回。
- 安全风险：zip 上传存在 Zip Slip、压缩炸弹和大文件风险，必须在服务层做硬限制；脚本执行还要额外受沙箱和权限控制。
- 体验风险：保留资源文件后，页面需要清晰解释“包资产已保留”和“脚本是否允许执行”的状态。

## 停点判断

- 架构边界变化：是，本阶段会引入包存储与运行时脚本权限控制。
- 数据模型变化：是，需要新增技能包和包文件索引相关表/字段。
- API 契约变化：是，新增上传、查询和权限切换接口。
- 鉴权或权限行为变化：是，新增“是否允许执行包内脚本”的显式权限语义。
- 人工确认：是，以上变化都需要确认后才进入实现。

## 验收标准

- OpenAPI 暴露技能包上传、查询和权限切换接口，并要求 Bearer 认证。
- 非平台管理员不能调用技能包管理接口。
- 上传包含根目录 `SKILL.md` 的 zip，可创建技能包记录并保留资源文件。
- 上传包含 `.codex-plugin/plugin.json` 和 `skills/*/SKILL.md` 的 zip，可创建多个技能候选并保留包资产。
- 非 zip、路径穿越、无 `SKILL.md`、超限包返回稳定错误。
- 前端技能管理页可上传 zip、查看包内容和切换脚本执行权限。
- 后端定向测试和前端静态检查通过，验证证据记录到 `verify.md`。

## 变更记录

### 2026-08-04 第 2 次变更（fix）

- 变更原因：关闭技能包脚本权限时，PATCH 请求返回 500。
- 变更内容：更新技能包后只刷新包标量字段，避免无关集合关系在异步 ORM 中额外加载；补充 `false` 布尔值契约回归检查。
- 影响章节：后端实现、风险、验收标准。
- 是否触发人工确认：否，接口契约和权限语义不变。
- 关联计划更新：沿用原实施计划，补充最小回归验证。

### 2026-08-04 第 1 次变更

- 变更原因：用户确认采用完整技能包路线，需要保留包资产并支持脚本执行权限。
- 变更内容：将方案从“预览后丢弃资源”切换为“技能包持久化 + 包级权限 + 运行时约束”。
- 影响章节：目标、范围、非目标、风险、停点判断、验收标准。
- 是否触发人工确认：是，新增架构、数据模型、API 和权限变化。

### 2026-08-04 初始版本

- 变更原因：支持技能管理直接导入市面常见 zip 技能包。
- 变更内容：定义 zip 导入预览接口、兼容包结构、安全限制和前端导入流程。
- 影响章节：全部。
- 是否触发人工确认：是，新增 API 契约。
