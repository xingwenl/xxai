# MCP 服务管理业界调研记录

## 调研问题

- 如何把现有 MCP 远程服务、工具同步、工具策略、智能体绑定和审计接成后台管理闭环？
- 服务删除如何兼顾配置清理与调用审计的不可篡改性？
- 远程 endpoint 和认证头管理需要哪些安全边界？

## 功能复杂度

- 级别：核心业务功能，涉及外部网络调用、工具权限、确认流程和审计数据。
- 选择理由：MCP 工具可能产生写入、财务或外部副作用，管理配置会直接影响智能体运行时能力。

## 现状差异

| 管理能力 | 当前后端 | 现有前端 | 本次需要 |
|---|---|---|---|
| 平台选择 | 有平台列表 | 未接入 | 接入 |
| 服务列表 | 缺失 | 调用旧 `/api/mcp-servers` | 新增平台级列表 |

| 编辑/启停 | 缺失 | 旧 PUT/toggle | 新增 PATCH |
| 删除服务 | 缺失 | 旧 DELETE | 新增带审计保护的 DELETE |
| 工具同步 | 已有 | 旧 sync-tools | 对接真实接口 |
| 工具策略 | 已有 PATCH | 旧工具接口 | 对接真实接口 |
| 智能体绑定 | 已有 PUT | 未接入 | 新增查询/解绑或补齐页面 |

## 方案比较

| 方案 | 优点 | 限制 | 与本项目的匹配度 |
|---|---|---|---|
| 继续使用旧全局 `/api/mcp-servers` | 前端改动少 | 后端不存在，无法平台鉴权和审计保护 | 低，不采用 |
| 无条件硬删除 MCP 服务 | 资源清理简单 | 会违反审计表 RESTRICT 外键，丢失调用追溯 | 低，不采用 |
| 平台级管理 + 停用 + 审计保护删除 | 保留审计一致性，权限边界清晰，符合运行时策略 | 有审计服务不能物理删除 | 高，采用 |

## 最终决策

- 选择方案：平台级 MCP 服务 CRUD、停用/启用、工具同步、工具策略管理、智能体绑定/解绑和审计列表。
- 删除语义：无关联调用审计时允许硬删除；存在审计记录时返回冲突错误，必须停用而不是删除。
- 安全语义：认证头加密保存，只返回 `has_auth_headers`；endpoint 由后端执行 URL、DNS 和私网校验。
- 前端：继续使用 `/system/mcp-servers` 入口，但重写 API 和页面为平台级真实契约。
- 不选择无条件硬删除的原因：数据库设计明确使用 `RESTRICT` 保护审计历史。

## 剩余风险

- 真实远程 MCP 服务同步依赖外部网络和服务协议兼容性。
- 删除冲突需要前端展示清楚“停用替代删除”的业务解释。
- 工具策略修改后的运行时效果需要真实会话联调验证。
