# 智能体详情工作台业界调研记录

## 调研问题

- 如何把分散的智能体基础信息、版本、知识库、技能、工具和模型用量收敛到一个可持续扩展的管理入口？
- 关联配置实时生效时，页面如何让用户理解生效边界并可靠完成关联与解除关联？
- 如何复用现有 API，避免为页面聚合重复建设新的运行时或统计数据源？

## 功能复杂度

- 级别：复杂业务功能。
- 选择理由：涉及智能体列表与详情路由、七个管理视图、知识库/技能/三类工具的跨模块联动，以及按智能体过滤的用量观察；知识库解除关联还需要新增 API 契约。
- 最低调研要求：参考官方前端状态管理实践、成熟配置式智能体平台、MCP 官方能力边界，并核对本仓库现有实现。

## 参考依据

### 来源 1

- 类型：官方文档
- 名称：TanStack Query Mutations
- 链接：https://tanstack.com/query/latest/docs/framework/react/guides/mutations
- 版本或发布日期：在线文档，2026-08-11 调研
- 调研日期：2026-08-11
- 核心做法：查询与变更操作分离；变更成功后精确失效相关查询；通过 mutation 的 pending、error 和 success 状态管理局部反馈。
- 对本项目的启发：关联开关只锁定当前行，成功后刷新当前能力与概览计数，失败后恢复开关并保留其他标签状态。

### 来源 2

- 类型：成熟配置式智能体平台
- 名称：Dify 文档
- 链接：https://docs.dify.ai/
- 版本或发布日期：在线文档，2026-08-11 复核既有调研结论
- 调研日期：2026-08-11
- 核心做法：将智能体的模型、指令、知识、工具和运行观察分成明确配置域，同时由单一应用/智能体上下文承载。
- 对本项目的启发：采用独立智能体详情工作台和一级标签页，不在列表弹窗中继续堆叠跨模块配置。

### 来源 3

- 类型：官方规范

- 版本或发布日期：2025-06-18

- 核心做法：MCP 服务负责工具发现，工具具有名称、描述、输入 Schema 和调用能力边界；客户端必须尊重服务与工具策略。
- 对本项目的启发：详情页沿用当前“按 MCP 服务关联智能体”的数据模型，展开查看有效工具，但不在智能体页重定义全局工具策略。

### 来源 4

- 名称：智能体运行时能力加载与模型用量事实表
- 链接：`apps/backend/app/modules/conversation/runtime.py`、`apps/backend/app/modules/model_usage/`、`apps/front/src/features/model-usage/index.tsx`
- 版本或发布日期：仓库 HEAD `e412f29`，2026-08-11

- 对本项目的启发：详情页只聚合已有真实数据，不新建统计表；知识库、技能和工具关联变更继续在下一轮对话加载时生效。

### 来源 5

- 类型：当前仓库管理 API
- 名称：智能体关联能力接口核对
- 链接：`apps/backend/app/modules/knowledge/router.py`、`skill/router.py`、`mcp/router.py`、`host_tool/router.py`、`builtin_tool/router.py`
- 版本或发布日期：仓库 HEAD `e412f29`，2026-08-11
- 调研日期：2026-08-11
- 核心做法：技能、MCP 服务、宿主工具和内置工具已有按智能体查询与变更能力；知识库只有关联接口，缺少按智能体查询关联和解除关联接口。
- 对本项目的启发：本次后端只补齐知识库关联闭环，不改变其他能力的模型、权限或运行时边界。

## 方案比较

| 方案 | 优点 | 限制 | 与本项目的匹配度 |
|---|---|---|---|
| 详情工作台 + 一级标签页 | 信息边界清楚，URL 可直达，可按标签独立加载，适合持续扩展 | 路由与页面组件增加，需要处理跨标签摘要刷新 | 高，采用 |
| 单页纵向工作台 | 首版结构简单，所有内容同时可见 | 页面过长，能力较多时定位和加载成本高 | 中，不采用 |
| 双层侧边导航 | 配置密度高，适合大量设置项 | 与全局侧边栏形成双重导航，窄屏复杂 | 中低，不采用 |

## 最终决策

- 选择方案：保留智能体列表页，新增独立详情工作台；详情页包含概览、配置、知识库、技能、工具、版本和用量七个一级标签。
- 选择原因：智能体是所有配置和用量的共同上下文，详情路由能把现有分散入口收敛成稳定的信息架构，并允许每个标签独立加载与失败隔离。
- 工具边界：内置工具和宿主工具按工具关联；MCP 沿用现有模型按服务关联，展开查看服务内有效工具。
- 生效边界：基本信息和能力关联保存后在下一轮对话生效；模型、系统提示词、温度和 API Key 继续通过新版本发布生效。
- 数据决策：用量复用现有 `model_usage_records` 汇总和明细接口，不计算缺乏价格快照支撑的历史费用。
- 对后续 spec、plan 或人工确认的影响：需要新增智能体详情读取、知识库关联查询和解除关联 API；属于 API 契约变化，进入实现前必须人工确认。

## 剩余风险

- 资料时效性：外部文档为在线资料，具体实现继续以当前仓库依赖与接口为准。
- 与本项目上下文的差异：Dify 的完整产品模型不直接映射本仓库；仅参考其按智能体聚合配置域的方式，不复制其数据模型。
- 尚未验证的假设：现有模型用量数据按日聚合足以支持 7/30 天趋势；知识库关联新增接口可以在不改变表结构的情况下复用现有仓储查询。
