# DSH「万物皆插件」思想借鉴落地规格

## 目标

- 把 `research.md` 的调研结论（方案 B：借鉴边界思想，做增量加固）落地为 4 个可执行的增量点 + 1 条平台原则，不引入 Cordis，不做运行时热替换。
- 目标对象：后端工具体系（`apps/backend/app/modules/tools/`）与执行链路（`apps/backend/app/modules/gateway/dispatcher.py`）的维护者；Harness 流程维护者。
- 完成后应产生可验证结果：依赖环检测在启动时快速失败；工具元数据字段就位且既有工具零回归；工具执行前后事件可被观测订阅；平台插件化原则写入常驻文档。
- 引用 `research.md` 关键结论：DSH 的"依赖显式化、事件即扩展点、配置层组合"值得借鉴；"无特权内核、运行时自进化"对本仓库是反模式，安全原语必须收敛。

## 范围

### 包含

1. **平台原则文档**：新增 `docs/harness/specs/plugin-boundaries.md`，固化"平台原语收敛、业务组合可扩展、不引入运行时热替换"三条原则，并映射到现有 basic/business/skill 分层与 `model_registry` 的角色路由。
2. **依赖环检测**：扩展工具注册表启动校验：
   - 支持业务工具声明依赖其他业务工具（当前 `depends_on` 仅支持基本工具键）；
   - 启动时做依赖缺失校验（已有）+ 依赖环检测（新增），环存在时快速失败并输出完整环路径。
3. **工具元数据标准化**：为 `BasicTool` / `BusinessTool` 增加统一元数据字段（`version`、`author`、`permissions`、`side_effect` 语义补全），所有字段提供默认值，既有工具注册零改动、零回归。
4. **工具执行前后事件钩子**：在 dispatcher 工具执行前/后发布异步事件（工具名、参数摘要、耗时、结果状态），先只做可观测（审计/遥测消费方），不拦截、不改造工具本体，不阻塞主执行路径。

### 不包含

- 运行时热替换 / 自进化：不允许在运行期生成、替换或卸载核心组件。
- 安全原语插件化：鉴权、SSRF 防护、密钥管理、资产权限隔离保持平台收敛代码，不作为可替换插件。
- 引入 Cordis 或任何插件运行时依赖。
- Agent 能力组合模板（工具绑定 + 技能 + 模型角色沉淀为可复用模板）：本期只写原则，模板化留待后续 request。

## 风险

- 依赖环检测误报风险：校验只对显式 `depends_on` 生效，报错信息包含完整环路径，便于定位；不推断隐式依赖。
- 元数据新增回归风险：新字段全部带默认值，装饰器签名向后兼容；通过既有工具注册测试覆盖。
- 事件钩子性能风险：事件异步发布、消费方失败不反噬执行链路；实施后以日志确认不阻塞。
- 文档与代码偏离风险：原则文档列入 Harness 审批检查点（后续涉及插件化的 request 必须引用）。

## 停点判断

- 是否涉及架构边界变化：是（依赖图校验、执行链路事件钩子属于架构边界）→ 进入实现前需人工确认。
- 是否涉及数据模型变化：否（无数据库表变更）。
- 是否涉及 API 契约变化：部分（工具元数据为内部契约；若后续要对前端或 MCP 暴露，需另行确认）。
- 是否涉及鉴权或权限行为变化：否（`permissions` 元数据本期只声明不 enforcement）。

## 验收标准

- `docs/harness/specs/plugin-boundaries.md` 存在，三条原则与现有分层映射清晰，可被后续 request 引用。
- 工具注册表启动校验包含依赖环检测：构造 A→B→A 环时启动失败并输出环路径；缺失依赖仍快速失败。
- `BasicTool` / `BusinessTool` 元数据字段就位；既有工具注册（`http_get`、`http_post`、`vision.describe`、`image_gen` 等）无需修改即可通过启动校验。
- dispatcher 在工具执行前/后发布异步事件；单元测试断言事件顺序与字段；全量后端测试通过、ruff 通过。
- `spec.md` 变更记录、`verify.md`、`acceptance.md` 按 Harness 规范补齐。
