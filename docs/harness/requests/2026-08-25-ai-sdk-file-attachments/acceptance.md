# 验收结论

## 2026-08-26 已发送图片即时展示 bugfix

已发送图片现在优先使用本地 Blob 地址立即展示，避免刚发送时因受保护资源请求失败而永久显示为空；刷新后的历史消息仍通过受保护资源地址加载。SDK 测试、类型检查和生产构建均通过。

## 2026-08-26 当前会话上传与非视觉模型降级 bugfix

已有会话中的后续上传已归入当前会话；非视觉模型明确拒绝图片内容时会自动降级为文字请求，不再因上游 400 导致整轮失败。降级后模型无法识别图片本身，这是模型能力限制，需配置视觉模型才能完成图片内容分析。

## 2026-08-26 图片展示与视觉模型输入 bugfix

本次 bugfix 已通过验收：前端用户消息可展示上传图片引用；后端在当前 Embed 主体和会话权限内加载图片，并将其作为多模态内容传给模型。图片 Base64 只存在于单次模型请求内，不写入消息历史。SDK 全量测试 94/94、后端附件/网关/会话测试 131 个通过（1 个条件跳过），类型检查、生产构建、Ruff 和差异检查均通过。

剩余风险：未使用真实供应商视觉模型联调。若当前 Agent 选择的是非视觉模型，上游仍可能拒绝图片或无法识图；需选择支持图片输入的模型后进行实际识图回归。整个附件 request 仍保持 active，文档解析、供应商能力矩阵和向量检索等后续范围未因此标记完成。

## 2026-08-26 baseUrl 增量

本次增量达到验收标准：SDK 新增可选 `baseUrl`，附件上传、状态查询、删除和资源下载统一使用该 HTTP 根路径；未配置时保留旧 endpoint 推导逻辑；README、Demo 和回归测试已同步更新。

剩余风险：原文件附件 request 的后端异步处理、真实供应商联调和向量检索仍未完成，本次不将整个 request 标记为 done。
