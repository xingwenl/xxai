# 设计说明

## 目标

让 AI 模型在处理当前消息时看到同一会话最近一段时间的历史聊天记录，默认保留最近 1 小时，并允许部署通过环境变量调整窗口。关键调研结论见 `research.md`：历史由后端可信读取并在模型调用前按窗口注入。

## 范围

- 后端配置 `CONVERSATION_HISTORY_WINDOW_SECONDS`，默认 3600 秒。
- 会话仓储按 `conversation_id` 和截止时间查询已完成历史消息。
- 非流式和流式模型调用都注入相同历史上下文。
- 增加运行时单元测试和 Harness 验证记录。

## 非目标

- 不新增或修改数据库表、字段和迁移。
- 不修改 SDK WebSocket/HTTP 请求协议，SDK 继续发送 `conversation_id`。
- 不新增 token 计数裁剪、摘要记忆或跨会话记忆。

## 风险

- 历史消息会增加输入 token 和模型成本。
- 窗口内的超长消息可能仍超过模型上下文限制。
- 工具调用历史只按已持久化文本消息映射，不能恢复完整的 tool call 参数。

## 停点判断

- 架构边界变化：否
- 数据模型变化：否
- API 契约变化：否
- 鉴权或权限行为变化：否
- 进入实现前人工确认：不需要

## 验收标准

- 默认配置为 3600 秒，可由 `CONVERSATION_HISTORY_WINDOW_SECONDS` 覆盖。
- 只把截止时间之后且状态为 `completed` 的 user/assistant/tool 消息传给模型，顺序保持正序。
- 当前消息始终是最后一条，历史不会重复当前消息。
- 流式与非流式调用均传入历史；无历史时行为与现有实现一致。
- 既有后端测试通过，新增测试验证窗口过滤、角色映射和调用顺序。

### 2026-08-10 第 2 次修复

- 变更原因：SDK 传输层未将已收到的 `conversationId` 放入后续 `message_send` 请求。
- 变更内容：WebSocket SDK 在发送聊天消息时附加顶层 `conversationId`，并增加回归测试。
- 影响章节：范围、验收标准
- 是否触发人工确认：否

### 2026-08-10 第 3 次修复

- 变更原因：`AgentClient` 未从网关事件顶层读取会话 ID，导致 SDK 内部消息和工具上下文的标识为空。
- 变更内容：统一以事件顶层 `conversationId` 同步 `AgentClient.conversationId`，保留 `session_ready.payload.sessionId` 兼容读取。
- 影响章节：验收标准
- 是否触发人工确认：否

### 2026-08-10 第 4 次修复

- 变更原因：需要定位浏览器、WebSocket 网关和会话运行时之间的会话 ID 丢失位置。
- 变更内容：增加不包含聊天内容和凭据的 `conversationId`/`requestId` 诊断日志。
- 影响章节：风险、验收标准
- 是否触发人工确认：否

### 2026-08-10 第 5 次修复

- 变更原因：payload 中的 `conversationId` 是字符串，直接与 PostgreSQL 整数主键比较触发类型错误。
- 变更内容：网关入口兼容 payload/顶层字段，将数字字符串校验并转换为正整数，非法值返回稳定错误。
- 影响章节：风险、验收标准
- 是否触发人工确认：否
