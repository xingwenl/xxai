# Phase 2D 管理后台设计说明

## 目标

- 补齐 AI Agent JS SDK Phase 2D 管理后台能力，让平台管理员能在后台配置 Agent、Embed Client、Origin 白名单、宿主工具策略、绑定关系和审计查询。
- 保留当前已经实现的智能体、知识库、技能和 MCP 管理页面，不做大范围重构。
- 采用 `research.md` 的结论：少页面、Agent 为中心，平台级资源池负责创建资源，Agent 或资源详情负责绑定配置。
- 完成后可通过前端页面和后端接口验证 Embed Client / Host Tool 的管理链路。

## 范围

### 已有能力复用

- 复用 `apps/front/src/features/agents/index.tsx` 作为智能体主入口。
- 复用 `apps/front/src/features/knowledge/index.tsx`、`apps/front/src/features/skills/index.tsx` 和 `apps/front/src/features/system/mcp-servers.tsx`。
- 复用后端已有 Embed Client 和 Host Tool 管理 API。

### 后端最小补充

- 新增平台更新接口，支持修改名称、编码、启用状态。
- 新增平台硬删除接口，删除平台及其级联资源。
- 新增读取 Embed Client Agent 绑定状态的管理接口。
- 新增读取宿主工具 Agent 绑定状态的管理接口。
- 新增读取宿主工具 Embed Client 绑定状态的管理接口。
- 将宿主工具策略重复创建从非结构化 `ValueError` 调整为稳定冲突错误。
- 不新增数据库表，不改变现有绑定语义。

### 前端新增

- 新增 `apps/front/src/features/platforms/index.tsx` 和 `/ai/platforms`：
  - 平台列表、创建、编辑、停用/启用、硬删除。
  - 删除前展示级联删除风险确认。
- 新增 `apps/front/src/api/embed-clients.ts`：
  - Embed Client 列表、创建、更新、轮换密钥。
  - Embed Client 绑定/解绑 Agent。
  - Embed Client 绑定/解绑宿主工具。
  - 读取绑定状态。
- 新增 `apps/front/src/api/host-tools.ts`：
  - 宿主工具策略列表、创建、更新。
  - 宿主工具绑定/解绑 Agent。
  - 宿主工具审计查询。
  - 读取绑定状态。
- 新增平台级资源页：
  - `/ai/embed-clients`：Embed Client 管理，Origin 白名单放入 Client 表单。
  - `/ai/host-tools`：宿主工具策略管理，包含 JSON Schema、sideEffect、确认策略、启停、绑定和审计轻量入口。
- 在侧边栏 `AI 管理` 中增加两个入口；不新增独立 Origin 页面，不新增大型审计中心。

### 模型用量统计增量

- 新增 `/ai/model-usage` 页面，使用单页汇总 + 明细结构。
- 新增平台管理员可访问的模型用量分页明细接口。
- 新增平台管理员可访问的模型用量汇总接口，返回总计、按 Agent、按 Embed Client、按日期聚合。
- 页面默认查询最近 7 天，支持平台、Agent、Embed Client、自然日范围筛选。
- 汇总卡片展示记录数、输入 token、输出 token、总 token。
- 明细表展示时间、Agent、Client、最终用户、会话、请求 ID、模型名和三类 token。
- 不新增数据库表，不改变 `model_usage_records` 写入语义，不展示 prompt、完整回复、token 或 secret。

## 非目标

- 不重做已有智能体、知识库、技能、MCP 页面。
- 不新增复杂 Agent 详情页，不重构全局平台上下文。
- 不新增权限模型，不改变当前平台管理员校验。
- 不在前端展示 `client_secret` 历史值、token、MCP 密钥或宿主工具敏感参数。
- 不实现真实远程 MCP 联调、生产数据合规导出或审计报表。

## 风险

- Embed Client secret 只展示一次，前端需要明确提醒管理员及时保存；关闭对话框后不可再查看。
- Origin 输入如果误填路径或通配符，会导致 token exchange 或 WebSocket 认证失败；前端需要做基础提示，最终以后端校验为准。
- 宿主工具 JSON Schema 输入容易出错；前端需要 JSON 校验，后端继续执行权威校验。
- 绑定读取接口属于 API 契约补充，进入实现前需要人工确认。
- 当前前端全量构建此前存在既有类型基线问题，可能影响完整验收。
- 直接聚合查询在明细量很大时可能需要组合索引或离线汇总；初版先以时间范围和平台隔离控制查询范围。

## 停点判断

- 架构边界变化：否，沿用现有 FastAPI 模块和 React 管理后台。
- 数据模型变化：否，本次不新增表、不新增字段、不新增迁移。
- API 契约变化：是，新增绑定读取接口、模型用量查询与汇总接口，修正宿主工具重复创建错误语义。
- 鉴权或权限行为变化：否，继续使用当前后台用户和平台管理员校验。
- 人工确认：已确认。用户已于 2026-07-30 确认“少页面、Agent 为中心”的 2D 方案，并允许新增最小绑定读取 API 与稳定冲突错误语义。

## 验收标准

- 后端 OpenAPI 暴露绑定读取接口，且接口均要求当前用户为平台管理员。
- 未授权用户不能读取或修改其他平台的 Embed Client、宿主工具策略、绑定或审计。
- Embed Client 页面可以完成列表、创建、编辑、启停、轮换密钥、绑定/解绑 Agent、绑定/解绑宿主工具。
- 平台页面可以完成列表、创建、编辑、停用/启用和硬删除；硬删除必须二次确认。
- Embed Client 创建和轮换后只在当前结果对话框展示 `client_secret`，列表和编辑表单不展示明文密钥。
- Origin 白名单在 Client 表单中维护，前端提示精确 Origin 规则。
- 宿主工具页面可以完成策略列表、创建、编辑、启停、绑定/解绑 Agent、绑定/解绑 Embed Client、查看最近审计。
- 宿主工具 JSON Schema 在前端提交前检查为合法 JSON 对象，后端仍保持最终校验。
- 模型用量页面可以按 Agent、Embed Client、自然日范围筛选，汇总和明细同步刷新。
- 模型用量汇总接口返回总计、按 Agent、按 Client、按日期三种稳定结构，空数据返回零值和空数组。
- 模型用量明细接口分页稳定，且只允许平台管理员读取当前平台数据。
- 前端 mutation 成功后刷新对应 query，页面不保留过期绑定状态。
- 定向后端测试、Ruff、前端 ESLint/Prettier 或可执行的最小替代验证有真实记录。
