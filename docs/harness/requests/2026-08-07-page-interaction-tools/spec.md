# 设计说明

## 目标

为 `apps/ai-sdk` 增加无需业务方逐个注册元素的页面感知与基础操作能力。Agent 可读取当前宿主页面视口中的语义内容，定位按钮/输入框等元素，并在权限和确认规则允许时点击、输入、滚动、等待和提取内容。

调研结论见 `research.md`：采用 WAI-ARIA 语义快照、临时元素引用和执行前重新校验；不将原始 HTML、任意 CSS/XPath 或远程浏览器控制框架暴露给模型。

## 范围

- 在现有宿主工具链上增加内置工具：`page_snapshot`、`page_click`、`page_type`、`page_scroll`、`page_wait`、`page_extract`。
- 只读取当前顶层文档的当前视口；滚动后要求重新观察。
- 使用 `dom-accessibility-api`、`aria-query`、`tabbable` 等轻量库辅助生成语义信息。
- 快照包含标题、脱敏 URL、可见文本、角色、accessible name、值和控件状态；限制元素数、文本长度和结果大小。
- 操作使用 `snapshotId` 与临时 `ref`，执行前校验快照版本、元素存在性、可见性、语义和可操作状态。
- 沿用现有 `ToolSideEffect` 与确认 UI：读取/滚动/等待为 `none`，普通输入为 `write`，导航和高风险按钮需要确认。
- 明确拒绝密码框、文件输入、跨域 iframe、任意 JavaScript、任意 selector 和任意 URL 导航。
- 增加 SDK 单元、协议、浏览器集成和构建产物验证。
- 页面工具执行受调用次数和累计时长预算限制；超过任一预算立即返回稳定错误，不再执行页面函数。

## 非目标

- 不替代现有业务语义工具 `registerTool()`。
- 不支持 Playwright、Stagehand、browser-use 的远程浏览器控制。
- 不在第一版实现 Shadow DOM、复杂画布坐标操作或跨域 iframe 操作。
- 不自动判断业务操作成功；通过 `page_wait` 和再次 `page_snapshot` 让模型确认状态。
- 不改变后端工具白名单的最终授权原则。

## 风险

- DOM 动态更新会使 `ref` 失效，必须返回稳定的 `page_snapshot_stale` 并要求重新快照。
- 页面文本是不可信输入，不能改变系统提示、工具权限或确认策略。
- 误触提交/删除/支付等按钮会产生业务副作用，必须结合语义、关键词和后台策略进入确认。
- 快照可能包含个人或业务敏感信息，需沿用现有脱敏、长度限制和审计规则。
- Safari/Firefox 与 Chromium 在可见性、事件和可访问性实现上存在差异，需要真实浏览器回归。

## 停点判断

- 是否涉及架构边界变化：是，新增 SDK 页面工具适配层和快照/引用状态。
- 是否涉及数据模型变化：否，沿用现有宿主工具审计模型；如实施发现需要持久化快照，必须另行审批。
- 是否涉及 API 契约变化：是，新增内置工具定义和 WebSocket 工具调用载荷。
- 是否涉及鉴权或权限行为变化：是，新增自动发现工具及风险分级，但后端授权仍为最终边界。
- 结论：进入实现前需人工确认 API 契约和权限行为。本次用户已确认设计方向，正式实现前仍需对规格和实施计划作最终审批。

## 验收标准

- `page_snapshot` 仅返回当前视口中可见、可交互元素的结构化语义信息，并遵守大小限制。
- `page_click`、`page_type` 只接受有效 `snapshotId/ref`，页面变化或元素不匹配时不执行并返回稳定错误。
- 输入框、搜索框、可编辑区域可按 replace/append 执行；密码框和文件框始终拒绝。
- 滚动、等待和重新快照可用于处理动态内容，不自动重试有副作用操作。
- 导航、提交、删除、支付等高风险操作进入现有确认 UI；重复确认不会重复执行。
- 不向模型、WebSocket 或日志发送任意脚本、跨域凭据、未脱敏敏感参数或任意 URL。
- 现代 Chrome、Edge、Safari、Firefox 的定向测试、typecheck、build 和包体积检查通过。
