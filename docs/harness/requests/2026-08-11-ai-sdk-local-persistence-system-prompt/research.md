# 业界调研记录

## 调研问题

本次需要让 `apps/ai-sdk` 支持可参与模型回答的 `systemPrompt`，并把消息与会话 ID 缓存到浏览器，使页面刷新后继续同一后端会话，同时允许用户清空本地记录开启新会话。

## 功能复杂度

- 级别：普通业务功能
- 选择理由：涉及 SDK 生命周期、本地持久化和 WebSocket 请求契约，并需要后端把调用方提示词合并进模型上下文。
- 最低调研要求：浏览器存储官方资料、主流 AI 对话状态资料，以及现有项目的后端会话历史实现。

## 参考依据

### 来源 1

- 类型：官方文档
- 名称：MDN Web Storage API
- 链接：https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API
- 版本或发布日期：持续更新，调研时可用版本
- 调研日期：2026-08-11
- 核心做法：`localStorage` 按源保存字符串键值，浏览器会话之间保留数据；容量、隐私模式和禁用存储可能导致写入失败。
- 对本项目的启发：SDK 可将可序列化的消息和会话 ID 保存为单个版本化 JSON，并对存储异常降级为内存模式。

### 来源 2

- 类型：官方文档
- 名称：OpenAI Conversation State
- 链接：https://platform.openai.com/docs/guides/conversation-state
- 版本或发布日期：持续更新，调研时可用版本
- 调研日期：2026-08-11
- 核心做法：应用可使用会话标识让服务端保存上下文；客户端不必每次重复发送完整历史。
- 对本项目的启发：本地缓存只负责恢复 UI 和可信会话 ID，模型上下文继续由后端按会话 ID读取，避免客户端篡改完整历史。

### 来源 3

- 类型：本项目成熟实现
- 名称：Embed 网关会话历史上下文
- 链接：`docs/harness/requests/2026-08-10-conversation-history-context/research.md`
- 版本或发布日期：2026-08-10
- 调研日期：2026-08-11
- 核心做法：后端按 `conversation_id` 查询时间窗口内已完成消息，并在流式模型调用前注入；SDK 后续消息携带会话 ID。
- 对本项目的启发：复用现有会话机制，仅扩展请求中的调用方 `systemPrompt`，不把 SDK 本地历史作为模型可信输入。

## 方案比较

| 方案 | 优点 | 限制 | 与本项目的匹配度 |
|---|---|---|---|
| SDK 发送完整本地历史 | 刷新恢复直观 | 请求大、历史可篡改、与后端历史重复 | 低 |
| SDK 缓存 UI 消息和 `conversationId`，后端按 ID加载历史 | 保持现有可信边界，刷新后上下文连续，清空即可新会话 | 需要处理浏览器存储异常和协议字段 | 高 |
| 只缓存消息、不缓存会话 ID | 实现简单 | 刷新后会创建新后端会话，无法延续上下文 | 低 |

## 最终决策

- 选择方案：版本化 `localStorage` 缓存 `messages` 与 `conversationId`；`systemPrompt` 随每次 `message_send` 请求发送，后端与 Agent 系统指令合并。
- 选择原因：满足刷新续聊和清空新会话，同时复用现有服务端历史窗口和会话权限校验。
- 不选择其他方案的原因：不把客户端完整历史作为模型可信上下文；不丢失会话 ID。
- 对后续 spec、plan 或人工确认的影响：WebSocket `message_send` payload 新增可选 `systemPrompt`，属于 API 契约变更，已获得用户确认后进入实现。

## 剩余风险

- `localStorage` 可能不可用或容量不足，SDK 需捕获异常并保持内存功能可用。
- 本地缓存可被页面脚本读取，不能保存 token、密钥或敏感凭据；消息仅作为展示缓存。
- 旧缓存或非法 JSON 需要忽略并清理，不能阻塞 SDK 初始化。
- system prompt 属于调用方输入，基础 Agent 指令和服务端工具权限仍保持更高可信边界；本次不新增独立配置表。
