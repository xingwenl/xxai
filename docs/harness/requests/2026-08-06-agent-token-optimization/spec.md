# Agent 对话 Token 优化规格

## 目标

降低 Agent 每轮对话的输入 Token，避免无关知识片段和未使用技能指令进入模型上下文，同时保持知识库引用和技能调用行为正确。

## 范围

### 包含

- `KnowledgeBase` 增加 `retrieval_threshold`（默认 0.5）和 `retrieval_top_k`（默认 5）。
- 创建、更新、读取知识库 API 和后台配置页面支持两个字段。
- 检索按 cosine similarity 过滤，未达到阈值时不注入知识库。
- 多知识库结果按分数合并、去重，并受全局上下文字符预算限制。
- 技能常驻上下文仅注入名称、slug、描述和脚本能力；完整指令通过受控 `load_skill` 工具按需读取。
- 增加检索与技能加载相关日志和测试。

### 不包含

- 查询改写、重排模型、自适应检索。
- 同一知识库内按 `source_type` 配置独立阈值。
- 改变鉴权、权限和 Agent 绑定语义。

## 方案与数据流

1. runtime 加载已绑定知识库和技能元数据。
2. 对每个知识库生成 query embedding，查询当前索引版本的候选 chunk。
3. 将 cosine distance 转换为 `similarity = 1 - distance`，过滤 `similarity >= retrieval_threshold`，保留该库最多 `retrieval_top_k` 条。
4. 跨知识库按 similarity 降序合并，按文档/文本去重，并应用全局字符预算。
5. 有结果才构建 citation 并注入 system prompt；无结果时不注入，grounded 为 false。
6. system prompt 常驻技能清单只提供元数据。模型调用 `load_skill(slug)` 后，服务端仅从当前 Agent 已绑定且启用的技能返回完整指令；同一轮缓存已加载内容。

## API 与数据模型

- 新增字段均为非空、有服务端默认值，历史数据迁移后行为保持原固定 Top K=5 和无阈值过滤的兼容默认之外，默认阈值 0.5 会主动过滤低相关结果。
- `retrieval_threshold` 约束为 0 到 1；`retrieval_top_k` 约束为 1 到 20。
- 这是数据模型和 API 契约变更，已获得用户确认后再实现。

## 风险与回滚

- 低阈值可能继续注入噪声，高阈值可能漏召回；通过日志记录分数分布，支持调整配置。
- 技能加载工具必须校验绑定关系，禁止任意路径和未授权技能读取。
- 回滚方式为回退应用代码并执行迁移 downgrade；字段保留不影响历史数据。

## 验收标准

- 知识库创建、编辑、列表 API 和前端表单能读写两个新字段。
- 低于阈值的 chunk 不进入 citations；没有命中时 system prompt 不出现知识库段落。
- 每个知识库结果数不超过其 `retrieval_top_k`，最终上下文不超过预算。
- 初始 system prompt 不包含技能完整 instruction；绑定技能可通过 `load_skill` 获取完整内容，未绑定技能不可获取。
- 现有知识库、对话、技能和前端测试通过。
