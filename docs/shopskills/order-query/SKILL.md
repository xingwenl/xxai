# 订单查询（order-query）

## 何时使用

当用户询问订单相关数据时使用，例如：

- 「查一下我的订单 / 今天的订单 / 最近 7 天订单」；
- 「查 XX 店 / 美团平台的订单」「统计这几天的订单金额和数量」；
- 询问某笔订单的收货人、备注、商品、金额、配送时间等。

本技能只做**只读订单查询**；改价、上下架、退款等写操作不在此技能范围内，遇到写操作需求如实告知用户暂不支持或走平台操作。

## 取数方式（必须先调用工具）

订单数据只能通过已绑定的内置工具 **`order_query`** 获取，技能自身不访问接口、不持有用户 token。用户未绑定该工具时，技能不可用，应告知管理员启用。

## 参数口径

把用户口语换算成工具入参：

- `start_date/end_date`：用户说「今天」→ 两者都是今天；「最近 7 天」→ 今天往前推 6 天到今天；格式固定 `YYYY-MM-DD`（北京时间）。拿不准时间跨度时先向用户确认。
- `platform_type`：用户说美团/饿了么/淘宝等平台时填对应代码（如 `MT`）；不说则省略。
- `keyword`：用户给出店铺名或订单号关键词时传入。
- `page/page_size`：只查最近几条时 `page_size` 按需（默认 20）；需要翻页时逐页调用。
- 不传任何筛选时表示查询最近订单（工具默认按下单时间倒序）。

## 输出规范

- 先给一句汇总（如「近 7 天共 N 笔订单」），再按单列出：平台/店铺名、下单时间、订单号、收货人、商品名 × 数量、金额、备注。
- 时间字段（`ctime/delivery_time/order_completed_time`）是 epoch 秒，展示前必须转成北京时间 `YYYY-MM-DD HH:mm:ss`，不要输出原始数字。
- 隐私：不主动展示手机号、骑手/发货人电话；工具返回里没有的字段不要编造或尝试向用户索要。
- 状态码含义不确定时不臆造，可原样给出并提示用户以平台为准。

## 错误处理

- 工具返回登录过期/认证失败：如实告知用户「店铺系统登录已过期，请重新登录后再试」，不要继续追问订单内容。
- 其它接口错误：把工具返回的错误信息原样转述，不编造原因。
- 工具返回「未绑定/不可用」类错误：提示联系管理员启用 `order_query` 工具。
